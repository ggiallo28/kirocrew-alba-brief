## Slack recap from Slackbot (`slackbot-<account id>.json`)
Some Slack workspaces cannot give Alba a token, so a daily step asks Slackbot for a recap instead.
- If `data/slackbot.json` has an entry for an account id, that IS this account's Slack source: read only `slackbot-<account id>.json` for it, and ignore any other `slack-<label>.json` file that may still exist for the same account (a leftover from before it used Slackbot - never report it as empty or unread).
- Item kinds: `channel` (real content of each channel, never just a message count), `mention`, `open_question`, `opportunity` (proposals, collaboration, job offers), `event` (events/meetups/webinars that could interest the user), `promo` (promotions, discounts, limited offers), `action` (a concrete thing to do, with a date when there is one), `link` (a notable link worth opening), `note`.
- Pick from it like from any other source, in this order of interest: mentions, unanswered questions, opportunities, events, promos, actions, then the one or two `channel` items that really matter. They compete for the same few places in the brief as everything else: a recap is one source, not a section. Skip support or noise channels that do not concern the user.
- Write its items as plain facts, like any other item: never mention Slackbot or the recap in a title, tag or body. If `complete` is false or there is a `note`, add ONE `unread` line saying which channels the recap did not cover, and nothing about it inside the items.
- A single item of kind `unavailable` means sign-in is needed: one `unread` line, no invented content.
